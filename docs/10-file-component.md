# 10 — File component and attachments

`discord.ui.File` displays an uploaded attachment within a V2 layout. It is useful for transcripts, exported reports, generated configuration files, or logs that belong alongside the message text.

## Upload and reference a file

```python
import discord

attachment = discord.File("./exports/transcript.txt", filename="transcript.txt")
panel = discord.ui.Container()
panel.add_item(discord.ui.TextDisplay("# Ticket transcript"))
panel.add_item(discord.ui.Separator())
panel.add_item(discord.ui.File(media="attachment://transcript.txt"))
layout.add_item(panel)
await channel.send(view=layout, file=attachment)
```

The filename after `attachment://` must exactly match the `filename=` passed to `discord.File`. Matching is case-sensitive in practice; avoid renaming one side without updating the other.

## Use an in-memory byte stream

```python
import io
import discord

payload = "Transcript generated by ZorveX Development.\n".encode("utf-8")
buffer = io.BytesIO(payload)
attachment = discord.File(buffer, filename="transcript.txt")

panel.add_item(discord.ui.File(media="attachment://transcript.txt"))
await channel.send(view=layout, file=attachment)
```

`BytesIO` is convenient for generated files. If you write to a stream and then reposition or reuse it, call `seek(0)` before upload. Use bytes for `BytesIO`; use `StringIO` only when a consumer expects text rather than a binary upload stream.

## File component versus `discord.File`

These objects serve different roles:

- `discord.File` represents the outbound upload handled by `send()`.
- `discord.ui.File` is a V2 layout item that points to the uploaded attachment.

Creating only one of them is not enough for the inline component pattern.

## Privacy and size

- Check that a transcript or log does not expose tokens, private messages, passwords, or unrelated personal data.
- Apply access controls to the channel and to any public link that accompanies the file.
- Handle upload size errors and network failures gracefully.
- Make generated filenames deterministic enough to reference, but unique enough to avoid accidental attachment confusion.

## A safer helper

```python
def make_transcript_view(filename: str) -> discord.ui.LayoutView:
    view = discord.ui.LayoutView()
    container = discord.ui.Container()
    container.add_item(discord.ui.TextDisplay("# Export ready"))
    container.add_item(discord.ui.TextDisplay("The requested export is attached below."))
    container.add_item(discord.ui.File(media=f"attachment://{filename}"))
    view.add_item(container)
    return view
```

Validate `filename` before using it in generated `attachment://` references. Do not let untrusted text inject arbitrary paths or attachment references.
